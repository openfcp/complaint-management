# 投诉文书生成规范

所有对外文档须走 **"Agent 生成 → 管理岗审核 → 部门负责人签发"** 三级流程；生成时自动嵌入"本文件由 AI 辅助生成，经人工审核确认"标识；未签发的文档不得对外发送。

## 1. 和解协议

- 生成逻辑：从谈判记录中提取共识要素（赔偿金额/补偿方式/履行时限）自动填充协议模板（模板见 `templates/settlement-agreement.md`）
- 模板要素：双方基本信息、争议事项概述、处理方案（赔偿/补偿/补救）、履行方式与时限、双方签字栏
- 人工审核重点：金额/时限/履行方式的准确性；条款无歧义

## 2. 案件处理记录

- 生成逻辑：自动汇编信息研判卡片 + 责任判定 + 谈判方案 + 谈判过程摘要 + 协议文本为完整处理记录
- 模板要素：案例编号、客户信息（脱敏）、投诉要点、研判结论、方案（上/中/下）、谈判过程、达成协议、签字确认
- 人工审核重点：过程记录完整性；结论与协议一致性

## 3. 典型案例复盘报告

- 适用：标记为"复杂/重大"的案件
- 模板要素：案例综述、归因分析、谈判经验总结、改进建议、知识条目更新建议
- 人工审核重点：经验总结的深度；改进建议的可操作性
- 复盘通过后推荐入库案例库（结构化字段：案例编号/业务类型/投诉原因/客户画像/处理方案/谈判过程/结果/经验教训/适用场景标签）

## 4. 处理决定告知函 / 核查答复函

- 生成逻辑：按监管格式要求生成标准化告知文书，自动填充处理结论和依据
- 模板要素：投诉人信息、投诉事项、核查过程、处理结论、法律依据、告知时限、救济途径
- 人工审核重点：法律依据准确性；格式合规性
- 时限要求对照：《银行业保险业消费投诉处理管理办法》（3号令）15/30/60 日处理时限；告知义务、回避制度、档案保存 ≥ 3 年

## 5. 监管报送材料

- 内容：年度投诉数量统计表、投诉业务类别分布、投诉地区分布、重大投诉情况说明、改进措施与成效
- 生成后经管理岗审核和部门负责人签发后导出；不直连监管报送系统，仅生成可导出的标准化材料
- 报送口径必须使用监管统计口径，与内部分析口径分别标注

## 6. 通用文书纪律

- 客户 PII 一律脱敏（姓名保留姓、证件保留前 3 后 4、手机号保留前 3 后 4、账号保留后 4 位）
- 引用法规/合同条款必须给出具体条款编号和原文，禁止凭记忆转述
- 文书中的金额、日期、时限字段生成后逐项列出让审核人复核
