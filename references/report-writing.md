# 投诉分析报告撰写规范

## 1. 报告框架（五部分，完整报告必须全部包含）

| 部分 | 内容 | 撰写要点 |
|------|------|---------|
| 第一部分：总体概览 | 投诉总量、发生率、处理效能、满意度 | 明确口径和统计周期；核心指标图表呈现；标注异常 |
| 第二部分：多维深度拆解 | 客户/产品/经营维度拆解 | 每维度至少 2 层拆解；交叉组合聚焦异常单元格 |
| 第三部分：专题分析 | 增长最快投诉类型、重复/升级投诉根因、监管关注问题、建模分析 | 每专题必须有诊断性结论；建模需说明技术路线 |
| 第四部分：问题根因与改进建议 | 系统性归因、针对性建议、闭环跟踪方案 | 根因指向具体责任节点；建议量化预期效果 |
| 第五部分：结论与展望 | 核心结论、下一步方向、模型优化计划 | 结论不超过 3 条，每条可直接对应管理行动 |

**金字塔原理结构要求**（报告行文）：① 核心结论先行（1-2 句关键发现）；② 数据概览（趋势图 + 分布图）；③ 根因分析（帕累托 + 漏斗法结论）；④ TOP 问题清单（区分内因/外因，附责任部门与督办时限）；⑤ 需提请上级支持事项。

## 2. 报告质量自检（输出前逐项执行并标注自检结果）

| 检查项 | 标准 |
|-------|------|
| 口径明确 | 每项数据标注口径来源 |
| 分类规范 | 严格遵循 JR/T 0169-2018 |
| 指标完整 | 关键指标体系全覆盖 |
| 维度充分 | 至少覆盖时间、客户、渠道三维 |
| 根因可执行 | 每个根因指向具体责任节点 |
| 建议有依据 | 每个建议有数据支撑和预期效果 |
| 闭环设计 | 每个建议有跟踪指标和责任部门 |
| 局限性声明 | 预测/建模部分附局限性说明 |
| 脱敏与标识 | 全文脱敏；AI 辅助生成标识齐全 |

## 3. 按报告类型裁剪

| 报告类型 | 结构 |
|---------|------|
| 分析摘要 | ≤ 300 字自然语言段落（简要分析请求） |
| 统计报表/交叉矩阵 | Markdown 表格，注明口径与周期 |
| 根因报告 | 问题 → 证据 → 根因 → 建议 → 跟踪（模板 root-cause-report.md） |
| 预警报告 | 信号 → 阈值 → 等级 → 建议 |
| 完整月报/季报/专项报告 | 五部分框架（模板 analysis-report.md） |
| 建模分析报告 | 技术路线 → 数据 → 模型 → 结果 → 局限性 |

## 4. 行文纪律

- 所有结论与建议可对应至少一个管理行动
- 分析逻辑从描述性 → 诊断性 → 预测性 → 指导性逐层递进，不跳层
- 交叉分析遵循"从少到多"，不直接使用 4 维以上交叉
- 涉及监管对标时注明监管口径和通报规则时效性；涉及同业对标时注明数据来源和可比性前提
- 数据样本量过小时主动标注结论置信度，建议扩大样本或谨慎引用
