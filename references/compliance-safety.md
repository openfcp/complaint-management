# 安全与合规规范

## 1. 数据安全

- 不得将用户提供的投诉原始数据存储到任何外部系统
- 客户 PII 输出脱敏规则：
  - 姓名：保留姓，名以 * 替代（张*）
  - 身份证号：保留前 3 后 4
  - 手机号：保留前 3 后 4
  - 银行账号：保留后 4 位
- 具体客户姓名、联系方式等敏感信息不得出现在分析报告中
- 涉及客户 ID、账户信息的中间过程数据在输出中同样脱敏

## 2. 合规要求

- 所有投诉分类编码严格遵循 JR/T 0169-2018，不得自行发明分类体系
- 涉及监管对标时必须注明监管口径和通报规则的时效性
- 涉及同业机构数据对标的结论必须注明数据来源和可比性前提
- 《生成式人工智能服务管理暂行办法》要求：AI 生成内容须标识、不得生成虚假信息

## 3. 人机协同边界（决策留人）

| 禁止事项 | 说明 |
|---------|------|
| 自主做出赔偿承诺 | 赔偿/补偿方案仅生成建议，须人工确认并校验授权边界 |
| 自主发送对外文件 | 对外文书须三级审核签发后人工发送 |
| 自主修改生效制度 | 制度修订仅出初稿与差异报告 |
| 自主派发整改任务 | 任务建议经管理岗确认后派发 |
| 自主拒绝投诉处理 | 黑灰产识别仅内部预警，仍按正常流程处理 |

黑灰产识别使用边界：识别证据链仅用于内部留存和监管报备，不得对外披露。

## 4. 输出责任

- 分析结论和数据计算结果仅供参考，不构成管理决策的唯一依据
- 建模分析输出必须附带局限性说明和置信区间
- 所有输出明确标注"本分析由 AI 辅助生成，建议人工复核关键结论"
- 对外文档嵌入"本文件由 AI 辅助生成，经人工审核确认"水印标识

## 5. 降级与兜底机制

| 降级触发条件 | 降级动作 |
|------------|---------|
| 知识检索/引用置信度 < 0.6 | 告知"未找到高置信度匹配，建议人工查阅"，不输出答案 |
| 责任判定置信度 < 0.7 | 输出"无法自动判定"并附已有信息，转人工研判 |
| 分类置信度 < 0.8 | 标记"待人工确认"，不自动入库 |
| 数据样本量过小 | 标注结论置信度，建议扩大样本或谨慎引用 |
| 建模 R² 偏低/置信区间过宽 | 说明模型解释力不足，建议补充特征或调整模型 |
| 历史数据周期不足 | 标注结论为"初步观察"而非"已验证规律" |

## 6. 能力边界（超出时如实告知）

- 实时流式分析：当前为批量分析，实时分析需接入数据流管道
- 自然语言工单的 NLP 语义自动分类：当前支持基于已分类数据的分析
- 跨机构数据整合：需各机构统一数据口径和格式，当前支持单机构分析和对标分析

## 7. 审计留痕

Skill 执行过程中的关键操作建议留痕：输入数据摘要、口径确认结果、生成的方案/文书、人工审核结果、关联案件编号。日志记录同样执行 PII 脱敏。
