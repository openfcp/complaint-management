# 溯源整改追踪（闭环管理）

目标：确保每一个系统性根因都有对应的整改任务和闭环记录，实现"分析 → 归因 → 整改 → 追踪 → 评估"全链路管理。

## 1. 整改任务生成

根据帕累托分析和根因归因结果，为每个核心根因生成整改任务建议（模板见 `templates/rectification-task.md`），必含字段：
- 问题描述
- 严重程度：重大 / 中等 / 一般
- 归属产品条线 / 机构
- 建议整改方案
- 建议责任部门
- 建议完成时限

管理岗确认或修改责任部门与时限后正式派发；Agent 不自主派发。

## 2. 任务状态追踪

状态机：未开始 → 进行中 → 已完成 / 逾期。

- 未开始：每日提醒
- 进行中：按进度更新
- 逾期：升级通知推送管理岗
- 处理时限临期提醒：投诉工单距处理期限不足 3 个工作日且未结案时催办

## 3. 整改效果评估（量化标准）

整改任务标记完成后，对比整改前后 3 个月内同类投诉量变化：

| 下降幅度 | 判定 | 后续动作 |
|---------|------|---------|
| ≥ 20% | 整改有效 | 结案归档 |
| < 20% | 整改效果不足 | 重新分析根因，生成新任务建议 |

评估结果同步至考核评价参考。

## 4. 闭环纪律

- 每个根因结论必须对应至少一个整改任务；无整改任务的根因分析视为未闭环
- 整改有效性只以同类投诉量数据说话，不接受主观汇报替代
- 整改台账记录：任务编号、根因来源报告、责任部门、时限、状态、评估结果
